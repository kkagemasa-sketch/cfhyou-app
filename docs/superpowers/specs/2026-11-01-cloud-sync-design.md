# CF表アプリ クラウド同期 設計書（案）

作成日: 2026-11-01　対象: 自分の端末どうし（PC・iPad・iPhone Duo）でCF表データを共有する

## 1. 結論（ひとことで）

**すでにアプリが使っている Firebase（cfhyou-shared）に、Googleログイン＋ブラウザ側暗号化で「本人専用の金庫」を作る。**
Cloudflare 側に新しくサーバーを作る必要はない。

- 今のアプリは「マンションマスター共有」のために Firebase（匿名ログイン・Firestore・Storage）を既に使っている（js/firebase-init.js）。
- そこに Google ログインを追加し、Firestore の `users/{本人のID}/...` だけを本人が読み書きできるようにする。
- お客様データは **送る前にブラウザで暗号化**（AES-GCM、合言葉から鍵を作る）。Firebase には暗号文しか置かない。

## 2. 画面の流れ

### 初回（各端末で1回）
1. ヘッダーに「☁ 同期」ボタンを追加。押すと同期パネルが開く。
2. 「Googleでログイン」→ Google のログイン画面（ポップアップ／iPhoneはリダイレクト）。
3. 「同期の合言葉」を入力（8文字以上）。
   - 初めての端末で、クラウドに既にデータがあれば「合言葉が合っているか」を復号テストで確認。違えば「合言葉が違います」。
   - クラウドが空なら、この合言葉で暗号化を始める。
4. 合言葉はその端末の中（localStorage）に保存し、次回から聞かない。

### ふだん
- 「保存/読込」で名前を付けて保存すると、端末内（今まで通り IndexedDB）＋クラウドの両方に保存。
- アプリを開いたとき・保存/読込パネルを開いたときにクラウド一覧を取得し、端末内より新しいものがあれば一覧に「☁ 新しい版あり」と出す。クリックで取り込む。
- 自動保存（作業中の状態）もクラウドへ。**手が止まってから1分以内**（内容が変わっていなければ送らない）＋画面を閉じる・切り替えるとき＋「今すぐ送る」ボタン（2026-11-03 決定、当初案の30秒から変更）。別端末で開いたとき「他の端末（端末名）で編集した内容があります。読み込みますか？」と確認（勝手に上書きしない）。
- オフラインなら端末内だけに保存し、次にネットがつながった時に送る。

### 同期パネルにあるもの
- ログイン状態（Googleアカウントのメール）／ログアウト
- 最終同期時刻、クラウド上の件数
- 「合言葉を変更」（全データを新しい合言葉で暗号化し直す）
- 「この端末の合言葉を忘れさせる」

### 今までのデータを移す（複数端末OK・2026-11-02 追加）
- 同期パネルに「この端末の保存データをすべてクラウドへ送る」ボタン。端末ごとに1回押す。
- 端末内の名前付き保存（全部）と自動保存を暗号化してクラウドへ。元のデータは端末に残す（消さない・上書きしない）。
- 同じ名前が既にクラウドにある場合: 新しい方（updatedAt）を優先し、古い方は「名前 ＿旧・MM/DD」で別名保存（どちらも消さない）。
- 自動保存は「最後に編集した端末のもの」をクラウドの autosave にし、他端末の自動保存は「自動保存（端末名・日時）」として名前付きで残す。
- 合言葉は全端末で同じものを使う。移したあと端末内を消すかは本人確認後（勝手に消さない）。

## 3. 保存の仕組み

```
Firestore
└ users/{uid}                 … uid = Google ログインの本人ID
   ├ meta                     … {kdfSalt, check(合言葉検証用の暗号文), updatedAt}
   ├ slots/{保存名}           … {name, savedAt, updatedAt, enc(暗号文 base64), bytes}
   └ autosave                 … 自動保存（同じ形）
```

- 暗号化: WebCrypto。合言葉 → PBKDF2(SHA-256, 20万回, salt) → AES-GCM 256bit。1件ごとに新しい IV。
- 1件の大きさ: 現状 13KB 程度（CF表を複製しても数十KB）。Firestore の上限 1MB に対して余裕あり。
- 衝突: `updatedAt` が新しい方を優先（last-write-wins）。一覧には端末内とクラウドの両方の時刻を出し、人が選べるようにする。
- 既存機能への影響: ログインしていなければ **今まで通り何も変わらない**。チームの他メンバーの使い方にも影響しない。

## 4. 安全性

| 守るもの | 仕組み |
|---|---|
| 他人が読めない | Firestore ルールで `users/{uid}` は本人（request.auth.uid == uid、かつ Google ログイン）だけ許可 |
| Firebase の中の人・漏えい | 暗号文しか置かない。合言葉はサーバーに送らない |
| 通信 | HTTPS のみ（既に） |
| 共通パスワードを知る他メンバー | 同期領域は Google ログイン必須なので触れない |
| 合言葉を忘れた | クラウドのデータは復元できない。端末内の保存・ファイル保存は残る。「合言葉をリセット（クラウド側を空にして作り直す）」を用意 |
| 保存場所（国） | Firebase プロジェクトのリージョンを要確認（asia-northeast1 = 東京なら国内）。暗号化済みなので内容は読めないが、プライバシーポリシーに「暗号化したうえでクラウド保管」の一文を追加する |

## 5. Firebase コンソールでやってもらう作業（私にはできない部分）

1. Authentication → Sign-in method → **Google を有効化**。
2. Authentication → Settings → 承認済みドメインに `cfhyou.pages.dev` と `kkagemasa-sketch.github.io` を追加（localhost は既定で可）。
3. Firestore → ルールに以下を追加（既存の mansions のルールは残す）。
   ```
   match /users/{uid}/{document=**} {
     allow read, write: if request.auth != null
       && request.auth.uid == uid
       && request.auth.token.firebase.sign_in_provider == 'google.com';
   }
   ```
4. Firestore のリージョンを確認して教えてください（プロジェクト設定 → 既定の GCP リソースロケーション）。

## 6. 作業の段取り

| 段階 | 内容 | 確認方法 |
|---|---|---|
| 1 | Google ログイン＋同期パネル（ログイン/ログアウト・合言葉） | ローカルでログインできる・合言葉の検証が効く |
| 2 | 名前付き保存のクラウド保存・一覧・取り込み | PC で保存 → 別ブラウザで取り込める |
| 3 | 自動保存の同期と「他端末で編集中」確認 | 2つのブラウザで同時に開いて確認 |
| 4 | オフライン時の後送り・合言葉変更・リセット | ネット切断して保存→復帰で送られる |
| 5 | 本番反映（feature ブランチで検証後に main へ） | version.json と右上の版番号 |

各段階ごとに画面写真を見てもらい、OK をもらってから次へ進む。

## 7. 決めてほしいこと

- 合言葉の最低文字数（案: 8文字）
- 自動保存をクラウドに送る間隔（案: 30秒。短いほど安心だが通信が増える）
- 「☁ 同期」ボタンの置き場所（案: ヘッダーの「保存 / 読込」の隣）
