# CF表 ④資産「課税・一括」カードの入力整理 — 設計（2026-11-09）

## 目的
「課税・一括」カードは、「開始（歳）」が空欄なら保有中・入れると将来購入、という暗黙の仕組みで、「投資額」の意味もそれで変わっていた（保有中＝今の評価額、将来購入＝買う金額）。さらに「取得価格累計」との違いが分かりにくく、利回りが効いているかもカード上で分からなかった。
→ 「保有中」「これから買う」を最初に選ばせ、必要な欄だけ出し、カード下に結果の説明文を出す。

## 画面（js/assets.js）
- 一括投資の欄（`sec-stock-fields`）の先頭に切替「保有中」「これから買う」（`.tc.tc-mini`、hidden `sec-stk-mode-{p}-{id}` = `hold`|`buy`、既定 `hold`）。
- 保有中: **今の評価額**（`sec-stk-bal`）／利回り（`sec-div`）／**売る歳**（`sec-stk-redeem`）。その下に **買った値段**（既存の取得価格欄 `sec-basis` を一括のときだけ欄の下へ移動し、ラベルを「買った値段」、placeholder「空欄=評価額と同じ」に）。
- これから買う: **投資額**（`sec-stk-bal`）／**買う歳**（`sec-stk-age`）／利回り／売る歳。取得価格欄は出さない。
- 切替 `setStkMode(p,id,mode,keepAge)`: hidden・トグル・欄の表示・ラベル文言を切替。「保有中」にしたときは「買う歳」を空にする（保有中＝買う歳なし、という従来の計算ルールを守るため）。`keepAge=true`（読込時）は値を触らず、`live()` も呼ばない。
- `_secBasisLayout(p,id)`: 種別が一括なら取得価格の行を一括欄の直後（説明文の前）へ移し表示を mode で切替、それ以外は元の位置（積立欄の前）へ戻す。債券は非表示（従来どおり）。`setSecType` から呼ぶ。
- `updateBasisHint`: 一括のときは「空欄のため、今の評価額＝買った値段（含み益なし）とみなします…」（赤）／「※売るときの税金（利益の20.315%）の計算に使います」。一括の判定には `sec-stk-bal` を使う（従来は `sec-bal` を見ていたため一括では赤くならなかった）。
- 説明文 `sec-stk-preview-{p}-{id}`（積立保険の説明と同じ見た目、青系）。`calcStkPreview(p,id)` を `secRefreshCard` から呼ぶ（`live()`→`refreshAssetUI`→`secRefreshCard` の経路で入力のたびに更新）。
  - 保有中: 「今の評価額1,000万（買値800万）→ 利回り5%で65歳時点で約3,556万（含み益2,756万、売ると税引後 約2,996万）」
  - これから買う: 「40歳に1,000万を購入 → 利回り5%で65歳時点で約3,386万（…）」。買う歳が空なら「「買う歳」を入れてください」。
  - 売る歳があればその歳（「売る65歳に約…、税引後の受取 約…」）。無ければ 65歳時点、開始が65歳以上なら10年後。
  - 年数は CF表の計算と同じ数え方（保有中: 現在年齢から T歳までの年数+1、これから買う: T−買う歳）。
  - 取り崩し設定が有効なら「※取り崩し設定あり。CF表は取り崩し後の残高です」を添える。
  - 投資額が0なら非表示。

## 計算（js/utils.js・cf-calc.js・contingency.js）
- 新しい共通関数 `secStkBasisInput(p,sid)`（utils.js）: 「これから買う」（hidden が `buy`、または買う歳>0）なら 0（＝投資額が買値）、保有中なら `sec-basis` の値。
- 一括投資の取得原価を読む所をこれに置き換える: cf-calc.js の securityState（stock）と資産行の `_stkBasisIn`、contingency.js の `_mgSecurityState`（stock）。
- 万が一の「死亡時現金化」（contingency.js）で一括投資の税計算は `val-bal` を利益としていたが、保有中で買った値段が入っていればそれを原価にする（通常CFの解約と同じ扱い）。
- 変わる挙動: 「これから買う」で取得価格が入っていた場合、今までは取得価格を買値として税計算していたが、今後は投資額を買値とする。保有中の挙動は変わらない。

## 保存・読込（js/save-load.js）
- `securities[].stkMode`（`hold`|`buy`）を追加。読込で無ければ `stkAge>0 ? 'buy' : 'hold'`。復元後に `setStkMode(p,id,mode,true)`。
- 既存ファイルはそのまま読める。欄のIDは変えない。

## 対象外
- 積立（課税・NISA）・債券・保険のカードは変えない（取得価格欄の位置・文言は従来どおり）。
- Excel・PDF・万が一タブの表の行は変えない。
- AI取り込みスキル（cf-hyou-torikomi）は同じ欄に入れるため変更不要（買う歳が入れば自動で「これから買う」になる）。

## 確認
- ローカル（port 9065）: 新規カード→保有中で評価額・買値・利回り入力→説明文の数字がCF表の該当年の値と一致。これから買うに切替→買う歳欄が出て取得価格欄が消える→説明文一致。保有中に戻すと買う歳が空になる。
- 保存→新規→読込で切替状態が戻る。旧データ（stkMode無し）は買う歳の有無で表示が決まる。
- `node tools/check.js`、コミット前テスト（golden・印刷・Excel比較）が通ること。
